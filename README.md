# ShareTrip Notification Service

Бэкенд-микросервис на Go для асинхронной обработки событий и рассылки уведомлений пользователям проекта ShareTrip.

## О проекте
Сервис потребляет события из брокера очередей **Kafka** (топик `trip.events`), реализуя паттерн **Idempotent Receiver** (идемпотентный потребитель). Это позволяет обрабатывать сообщения с гарантией Exactly-once (строго один раз), исключая дубликаты за счет встроенных транзакций PostgreSQL. 

Параллельно работает легкий HTTP-сервер на Fiber для внутренних API-вызовов.

## Стек технологий
- **Go 1.22+**
- **Kafka** (`segmentio/kafka-go`)
- **PostgreSQL** (`jackc/pgx/v5`)
- **Fiber** (HTTP-фреймворк)

## Сборка и запуск

1. Скопируйте пример конфигурации и, при необходимости, настройте `.env`:
```bash
cp .env.example .env
```

2. Для запуска сервиса локально (предварительно убедитесь, что база Postgres и Kafka запущены через `docker-compose` соседнего сервиса `share_trip`):
```bash
go run ./cmd/notification
```

3. Для сборки бинарного файла:
```bash
go build -o ./bin/notification ./cmd/notification
```

## Ключевые архитектурные решения
- **Graceful Shutdown:** Плавное, скоординированное завершение работы Fiber и Kafka-консюмера через `errgroup`.
- **TxRunner & RunInTx:** Изолированный транзакционный слой репозитория, не протекающий в бизнес-логику.
- **Poison Pill Handling:** Отлов битых сообщений и доменных ошибок с автоматическим коммитомオフсета для предотвращения застревания очереди.
- **Local Retry-Loop:** Защита от системных сбоев (отключение БД возвращает процесс в цикл ожидания, а не крашит приложение).
